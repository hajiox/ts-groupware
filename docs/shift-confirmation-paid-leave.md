# 半休を含むシフトの確定保存

2026-10-01: 製造の10月前半シフトで、半休の有給同期が失敗し、勤務内容だけが保存されて確定状態に進まない問題を修正。

パートの有給賃金は過去3ヶ月の平均勤務時間を使う。平均501分の半休なら計算時間は250.5分になる。DBと勤怠表示では整数の分数を使うため、保存時間は251分へ丸める。支給金額は従来の250.5分から円単位で丸め、保存時間の丸めによって金額を変えない。

半休時の実勤務時間と平均に基づく有給計算時間は別の値であり、251分の有給と240分の勤務は両立する。DBの大小比較は `ordinary_wage` かつ `raw_payload.wage_basis=three_month_average_hours` の場合のみ免除する。通常のシフト時間を基準にする半休の制限、非負の時間・金額、取得日数、残日数の承認処理は維持する。既存データの書換えは不要。

画面はAPIの `finalized=true` と再読込した同じ期間の `status=confirmed` の両方を確認してから、確定成功を表示する。

検証:

- `pnpm test:paid-leave-shift-sync`: 実賃金計算、有給同期、確定APIの正常系・失敗系。
- `pnpm test:shift-confirmation-ui`: 実画面関数の確定状態確認・保存失敗・一時保存。
- DBの回帰検証は一時表・架空データとROLLBACKを使い、実スタッフの有給残数やシフトには保存しない。
- リポジトリの型チェック、lint、production build。

適用するDB変更は `202610010002_paid_leave_half_day_average_minutes.sql`。更新後は管理画面を再読み込みして通常の「確定保存」を実行する。勤務内容の入力し直しは不要。
