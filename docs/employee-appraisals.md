# 社員査定

管理 → 査定（直接リンク `/admin?tab=appraisals`）。画像指定の10項目を1〜5のスライダーで評価する。1は改善必要、2は劣る、3は普通、4は良い、5は非常に良い。初期状態は未評価で、全項目評価後に完了できる。各備考は任意・2000文字以内。プライオリティーは参考表示のみで加重計算しない。

同じ画面の「面談で伝える内容」には、会社が求めるチームワーク・スキル・コスト意識・要望確認と、ハラスメントの説明・相談窓口を表示する。管理者は対象者へ話した項目を「説明済み」にチェックし、査定と一緒に保存する。途中の状態も下書き保存でき、チェック数は査定完了の条件にはしない。

対象月・査定者・対象者の組ごとに保存。下書きから再開でき、完了後も修正保存できる。保存競合は409で拒否し、画面の入力を保持する。本人への通知・公開は行わない。

## 担当と権限

- 役員は全査定の閲覧と担当設定が可能。査定入力は役員・管理者とも明示的に割り当てられた在籍者に限り、管理者は自分の査定だけ閲覧できる。
- 管理 → 査定 → 査定の担当設定で査定者を選び、部下へチェックする。既存データに直属関係がないため、部署一致から無断で担当を推定しない。
- TSG君・未承認者・一般ユーザーは査定操作不可。本人・役員・退職者は査定対象から除外。
- テーブルとRPCはanon/authenticatedに公開せず、セッションと担当を検証したAPIがservice_roleでアクセスする。

## 反映

初期スキーマは `supabase/migrations/202609110001_employee_appraisals.sql`（参照用同一SQL: `sql/062_employee_appraisals.sql`）。面談確認は `supabase/migrations/202609160001_appraisal_talk_checklist.sql` をTSG本番へ適用してからアプリを反映する。既存査定には5項目すべて未チェックの初期値を補い、旧保存RPCも移行中の互換用に残す。初回は役員が担当を設定する。
